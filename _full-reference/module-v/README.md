# Модуль В. Клиентская часть «Кухни мира» (SPA)

Одностраничное приложение (SPA) платформы рецептов для компетенции
«Веб-технологии» (чемпионат «Профессионалы», 2027).

**Стек:** Vue 3 + Vite + vue-router + axios + Laravel Echo / pusher-js.
**Стили:** локальная подборка классов, совместимая с разметкой Bootstrap 5
(CDN не используется — файл лежит в исходниках).

## 2. Сборка и публикация

На площадке (Node.js + npm с офлайн-кэшем):

```bash
cd source
npm install
npm run build
```

После сборки появится папка `source/dist`.

**Что публикуется на веб-хост** (адрес вида `http://xxxxxx-m5.web.lan`):

1. Содержимое `source/dist` → в **корень** виртуального хоста `{{host}}`
   (там окажутся `index.html`, `assets/`, `favicon.svg`, `.htaccess`).
2. Каталог `source` с исходниками → в подпапку **`source`** того же хоста,
   чтобы выполнялось требование «исходники находятся в папке source»
   (итог: `{{host}}/source/` содержит исходный код проекта).

Итоговая структура на сервере:

```
{{host}}/                ← собранное приложение (из dist/)
├─ index.html
├─ assets/
├─ favicon.svg
├─ .htaccess             ← SPA-fallback
└─ source/               ← ИСХОДНИКИ проекта (папка source по ТЗ)
   ├─ package.json
   └─ src/ … 
```

Файл `public/.htaccess` автоматически копируется в `dist` и включает
SPA-fallback на Apache — прямые ссылки на маршруты (`/login`, `/recipes/1`,
`/constructor` и т. д.) будут корректно открывать `index.html`.

> Если используется nginx, добавьте аналог: `try_files $uri $uri/ /index.html;`.
> Если `.htaccess` по какой-то причине не скопировался — создайте его вручную
> в корне хоста (содержимое — `source/public/.htaccess`).

### Вариант деплоя «сборка на сервере»
Скопируйте содержимое `source/` в подпапку `source` на сервере, выполните
`npm install && npm run build` там же, затем скопируйте `source/dist/*`
в корень хоста.

## 3. Настройка адреса API и заголовка Client

Все настройки — в файле **`source/.env`** (или `.env.local`):

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `VITE_API_BASE_URL` | Базовый URL REST API | `/recipe-api` |
| `VITE_CLIENT_LOGIN` | **Ваш логин** → заголовок `Client` в каждом запросе | `xxxxxx` |
| `VITE_WS_ENABLED` | Включить WebSocket-уведомления | `true` |
| `VITE_WS_KEY` | Ключ pusher-сервера | `app-key` |
| `VITE_WS_HOST` | Хост WebSocket (пусто = host текущей страницы) | `` |
| `VITE_WS_PORT` | Порт WebSocket | `6001` |
| `VITE_WS_CHANNEL` | Канал для уведомлений | `recipes` |

**Обязательно замените `VITE_CLIENT_LOGIN` на свой логин** перед сборкой:
заголовок `Client: <ЛОГИН>` добавляется ко всем запросам (требование критериев).

Если API находится на другом хосте, укажите абсолютный адрес, например:
`VITE_API_BASE_URL=http://xxxxxx-m5.web.lan/recipe-api`.

## 4. Реализованная функциональность (по ТЗ)

- **Регистрация** (`/register`): email, имя, пароль, повтор пароля, обязательный
  чекбокс согласия. Серверная валидация: сообщения рядом с полями + подсветка.
  Успех → переход на `/login`.
- **Авторизация** (`/login`): email + пароль, токен в `Authorization: Bearer`.
  Успех → переход на список рецептов.
- **Список рецептов** (`/`): доступен гостю и авторизованному. Для каждого рецепта —
  название, описание, калорийность, время приготовления, изображение. Сортировка
  в обе стороны: по дате создания, времени приготовления, калорийности (запрос к API).
- **Конструктор** (`/constructor`): ингредиенты в алфавитном порядке, drag-and-drop
  в область выбранных, добавление/удаление, повторный поиск при изменении набора;
  выводятся рецепты со ВСЕМИ выбранными ингредиентами, каждый со ссылкой.
- **Мои рецепты** (`/my`): только свои рецепты; название, описание, калорийность,
  изображение, кнопки редактирования и удаления.
- **Просмотр рецепта** (`/recipes/:id`): название, описание, калорийность, время,
  изображение, список ингредиентов.
- **Создание/редактирование** (`/create`, `/recipes/:id/edit`): название, описание,
  калорийность, изображение (файл), ингредиенты, время приготовления; серверная
  валидация с подсветкой полей; редактировать можно только свои рецепты.
- **Удаление** своих рецептов с модальным подтверждением; после удаления рецепт
  исчезает из списка.
- **WebSocket-уведомления**: подписка на канал `recipes` (событие `RecipeCreated`),
  всплывающее уведомление с названием рецепта и рабочей ссылкой, авто-закрытие,
  работает для гостей и авторизованных без перезагрузки страницы.
- **Токен** хранится только в `localStorage`; все прочие данные — с сервера.

## 6. Допущения (API не предоставлен в комплекте задания)

Полная документация API выдаётся в медиафайлах задания. Так как в данном окружении
её нет, REST-эндпоинты вынесены в `src/config/index.js` и легко перенастраиваются.
Принятые по умолчанию адреса (относительно `{{host}}/recipe-api`):

| Действие | Метод и путь |
|---|---|
| Регистрация | `POST /register` |
| Авторизация | `POST /auth` → `{ token }` |
| Список рецептов | `GET /recipes?sort=&page=&per_page=` |
| Детали рецепта | `GET /recipes/{id}` |
| Мои рецепты | `GET /recipes/my` (фолбэк: `GET /recipes?my=1`) |
| Поиск по ингредиентам | `GET /recipes/search?ingredients[]=` (фолбэк: `GET /recipes?ingredients[]=`) |
| Создание | `POST /recipes` (multipart/form-data) |
| Редактирование | `POST /recipes/{id}` + `_method=PUT` (multipart) |
| Удаление | `DELETE /recipes/{id}` |
| Ингредиенты | `GET /ingredients` |

Значения сортировки: `created_at_desc`, `created_at_asc`, `cooking_time_asc`,
`cooking_time_desc`, `calories_asc`, `calories_desc`.

Поля рецепта читаются устойчиво: калорийность — `calories` / `calorie_content` /
`calories_count`; изображение — `image` / `default_image` / `images[].thumbnail`.
Если реальная схема отличается, достаточно поправить `src/config/index.js`
и модуль `src/api/recipes.js`.
